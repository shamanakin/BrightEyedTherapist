# Guided EMDR — Session documentation protocol

This document defines what the Guided EMDR tool captures, how sessions flow across all protocols, and how the downloadable session report maps to EHR documentation. It is intended for clinicians and for maintainers extending the report generator.

**Privacy:** Clinical fields stay in the browser tab. A local draft may recover an accidental refresh. Nothing is sent to BrightEyedTherapist servers except BLS viewer sync (no clinical fields). The **downloadable `.txt` report** is the intended record for upload to your EHR. Add client identifiers in your EHR, not in the tool.

---

## 1. Session persistence model

| Layer | Purpose |
|-------|---------|
| In-memory | Active session while the tab is open |
| `sessionStorage` draft (`bet-guided-draft`) | Crash/refresh recovery only |
| Downloaded `.txt` report | EHR documentation (primary intentional save) |

**Warnings:** The app warns before **New session** or **tab close** if there are substantive notes and no download yet in this session.

**Optional filename label:** At download, you may enter a short label (e.g. initials) used only in the filename — not stored on BET servers.

---

## 2. Protocols and phase flows

### 2.1 Standard / Present trigger / Flash forward

Shared structure (phases 3–7); language differs by prong.

```
setup → assess → desensitize → install → bodyScan → closure
```

| Phase | Captured data |
|-------|----------------|
| setup | `protocolId` |
| assess | `targetLabel`, `image`, `nc`, `pc`, `voc`, `emotion`, `sudInitial`, `body` |
| desensitize | `sets[]` (n, SUD, note, time, podIndex), `sudCurrent` |
| install | `pc`, `voc` |
| bodyScan | `bodyScanClear` |
| closure | `closureType` (`complete` \| `incomplete`) |

### 2.2 Future template

```
setup → assess (no NC) → rehearse → install → bodyScan → closure
```

| Phase | Captured data |
|-------|----------------|
| assess | Target, coping movie (`image`), PC, VOC, emotion, SUD, body — **no NC** |
| rehearse | `movieRuns[]` (n, note, bump flag, time), `futureSituation`, `bumpUsed` |
| install / bodyScan / closure | Same as standard |

### 2.3 Recent event

```
setup → pods → [per POD: assess → desensitize → install → bodyScan → closure]* → wholeEvent
```

| Phase | Captured data |
|-------|----------------|
| pods | `eventLabel`, `pods[]` (label, assessComplete) |
| per-POD loop | Full assess + `sets[]` archived to `aspectRecords[]` on aspect completion |
| wholeEvent | `wholeEventSets[]`, `wholeEventSud` |

**Critical:** When advancing to the next POD, the engine snapshots the completed aspect into `aspectRecords` so prior set logs are not lost.

---

## 3. Set and run logging

| Action | Engine method | Storage |
|--------|---------------|---------|
| Desensitization set | `logSet({ note, sud })` | `sets[]` |
| Whole event set | `logWholeEventSet({ note, sud })` | `wholeEventSets[]` |
| Movie run / bump | `logMovieRun({ note, bump })` | `movieRuns[]` |

Each entry includes a timestamp (`at`). BLS host set counter is included in the report header when available.

---

## 4. Session report structure

Generated by `BET.GuidedReport.build()` into a plain-text file.

1. **Header** — Disclaimer, generated time, session start, protocol, phase at export, BLS set count, guidance on/off  
2. **Session overview** — Episode label, closure type, body scan, future situation  
3. **Points of disturbance** — POD list with processed/pending (recent event)  
4. **Completed aspects** — Archived snapshots (`aspectRecords[]`) with assess fields and set tables  
5. **Current / in-progress work** — Active target fields and any sets not yet archived  
6. **Movie runs** — Future template table  
7. **Desensitization set log** — Current `sets[]` (with POD column when applicable)  
8. **Whole event pass** — `wholeEventSets[]`  
9. **Session timeline (appendix)** — `sessionEvents[]` audit trail  
10. **Footer** — EHR upload reminder  

**Filename pattern:** `EMDR-Guided_{protocolId}_{YYYY-MM-DD}_{HHmm}_{optionalLabel}.txt`

---

## 5. Closure documentation

| Branch | Clinical meaning | Report field |
|--------|------------------|--------------|
| Complete | Reprocessing finished for this target/aspect | `closureType: complete` |
| Incomplete | Session ended with open target; container/calm place | `closureType: incomplete` |

Incomplete sessions should still be downloaded for EHR continuity. The report records the branch; follow your incomplete-session protocol in the chart.

---

## 6. Long and complicated sessions

**Many desensitization sets:** All sets appear in the set log table with SUD and notes. Timeline appendix lists each `set_logged` event.

**Multiple PODs (recent event):** Each completed aspect appears under **Completed aspects** with its own assess block and set table. Do not rely on the current target fields alone after advancing PODs.

**Interrupted session:** Use **Incomplete** closure, download the report, and upload to the EHR. Draft recovery may restore the tab after refresh; download remains the authoritative chart copy.

**New session:** Clears in-memory state and draft. Download first if you need a record.

---

## 7. EHR upload guidance

1. Complete or pause the session in the tool.  
2. Use **Download session report** (header or closure).  
3. Optionally add a filename label for your filing system.  
4. Upload the `.txt` file to the client chart (or paste from **Copy to clipboard**).  
5. Add client name/ID, date of service, and clinical interpretation in the EHR — the tool does not store those.
